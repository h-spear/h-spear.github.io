## **문제 풀이**

---

문제의 제한 조건은 다음과 같습니다.   
- 문자열 $S$, 최소 패턴 길이 $K$, 최소 반복 횟수 $M$ 
- $S$는 $0$과 $1$로만 이루어져 있습니다.
- $K + M \le \lvert S \rvert \le 1{,}000{,}000$
- $3 \le K \le 60$
- $3 \le M \le 1{,}000$

문제에서는 디지털 로직 내 길이가 $K$ 이상인 패턴이 반복되는지를 확인해야 합니다.   
길이가 $K$보다 긴 패턴이 반복된다면 해당 패턴의 앞 $K$자리도 동일하게 반복되므로, **길이가 정확히 $K$인 부분 문자열의 반복 여부만 확인하면 됩니다.**

따라서 문자열 $S$의 각 위치에서 길이 $K$인 부분 문자열을 추출해 등장 횟수를 세고, $M$번 이상 등장하는 패턴이 있는지 확인하면 됩니다.

코드에서는 문자열 $S$를 순회하면서 `substring()`으로 부분 문자열을 추출하고, `HashMap`을 사용해 각 부분 문자열의 등장 횟수를 셌습니다.   

```text
counts ← empty hashmap

for i ← 0 to |S| - K
    pattern ← S[i : i + K]
    counts[pattern] ← counts.getOrDefault(pattern, 0) + 1

maxCount ← maximum value in counts

if maxCount ≥ M
    print 1
else
    print 0
```

## **메모리 초과 코드**

---

메모리 초과의 원인은 `HashMap`에 데이터를 저장하는 방식에 있었습니다.   
처음 작성한 코드에서는 다음과 같이 부분 문자열 자체를 `HashMap`의 키로 저장했습니다.   
```java
Map<String, Integer> counter = new HashMap<>();     // 키의 타입은 String

int logicLength = S.length();
for (int i = 0; i < logicLength - K + 1; ++i) {
    String keyStr = S.substring(i, i + K);      // 길이 K인 부분 문자열 생성
    counter.put(keyStr, counter.getOrDefault(keyStr, 0) + 1);
}
```

## **메모리 초과 원인과 해결**

---

부분 문자열 자체를 키로 사용하면 서로 다른 패턴마다 `String` 객체와 `HashMap` 엔트리가 저장됩니다.   
최악의 경우에는 약 $1{,}000{,}000$개의 문자열과 엔트리가 생성될 수 있어 메모리 초과가 발생했습니다.   

이를 해결하기 위해 문자열을 `long` 값으로 변환하고, 변환한 값을 `HashMap`의 키로 사용했습니다.   
**<span style="background-color: yellow">변환 과정에서 임시 String 객체는 생성되지만, 이를 HashMap에 키로 보관하지 않으므로 메모리 사용량을 크게 줄일 수 있습니다.</span>**    

문자열의 각 문자가 $0$ 또는 $1$이므로 한 문자를 하나의 비트로 표현할 수 있습니다.   
또한 패턴의 최대 길이는 $60$이므로 변환된 값의 최댓값은 $2^{60} - 1$입니다.   
**이는 `long` 범위에 포함되므로 모든 패턴을 안전하게 변환할 수 있습니다.**   

변환 로직은 다음과 같이 작성했습니다.   
실제 이진법 변환과 비트의 순서는 반대이지만, 이 문제에서는 모든 패턴의 길이가 $K$로 같고 각 문자가 서로 다른 비트에 대응하므로 변환 결과가 중복되지 않습니다.   
따라서 패턴을 구분하는 데에는 문제가 없습니다.   

```java
private static long toLong(String numStr) {
    long number = 0;
    int length = numStr.length();
    long j = 1;
    for (int i = 0; i < length; ++i) {
        number += (numStr.charAt(i) - '0') * j;
        j <<= 1;
    }
    return number;
}
```

## **정답 코드**

---

- **시간 복잡도**: $O(\lvert S \rvert \cdot K)\$
- **공간 복잡도**: $O(\lvert S \rvert)\$

```java
import java.io.*;
import java.util.*;

public class Main {

    public static void main(String[] args) throws Exception {

        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st;

        String S = br.readLine();

        st = new StringTokenizer(br.readLine());
        int K = Integer.parseInt(st.nextToken());
        int M = Integer.parseInt(st.nextToken());

        Map<Long, Integer> counter = new HashMap<>();

        int logicLength = S.length();
        for (int i = 0; i < logicLength - K + 1; ++i) {
            long keyNum = toLong(S.substring(i, i + K));
            counter.put(keyNum, counter.getOrDefault(keyNum, 0) + 1);
        }

        boolean isStableLogic = max(counter.values()) < M;
        System.out.println(isStableLogic ? 0 : 1);
        br.close();
    }

    private static long toLong(String numStr) {
        long number = 0;
        int length = numStr.length();
        long j = 1;
        for (int i = 0; i < length; ++i) {
            number += (numStr.charAt(i) - '0') * j;
            j <<= 1;
        }
        return number;
    }

    private static int max(Collection<Integer> collection) {
        int max = Integer.MIN_VALUE;
        for (int x: collection) {
            max = Math.max(max, x);
        }
        return max;
    }
}

```

### **추가로 개선할 수 있는 부분**

제가 작성한 코드는 모든 부분 문자열의 등장 횟수를 센 뒤 최댓값을 구합니다.   
하지만 어떤 패턴이든 등장 횟수가 $M$에 도달하면 결과가 확정되므로, 즉시 반복을 종료할 수 있습니다.   

```java
for (int i = 0; i < logicLength - K + 1; ++i) {
    long keyNum = toLong(S.substring(i, i + K));

    int count = counter.getOrDefault(keyNum, 0) + 1;
    if (count >= M) {           // 하나라도 등장 횟수가 M 이상이면 결과 출력
        System.out.println(1);
        return;
    }
    counter.put(keyNum, count);
}
```

또한 매번 `substring()`과 `toLong()`을 호출하는 대신, 이전 패턴에서 맨 앞 비트를 제거하고 새로운 비트를 추가하는 방식으로 값을 빠르게 갱신할 수 있습니다.   
첫 패턴만 `toLong()`으로 계산하고, 이후에는 다음 로직을 사용해 다음 패턴의 값을 $O(1)$에 계산할 수 있습니다.   
```java
long keyNum = toLong(S.substring(0, K));   // 반복문 밖에서 첫 패턴 값으로 초기화
for (int i = 0; i < logicLength - K + 1; ++i) {
    // 현재 패턴의 등장 횟수 계산

    // 다음 패턴으로 갱신
    if (i < logicLength - K) {
        keyNum >>= 1;  // 맨 앞 비트 제거
        keyNum |= (long) (S.charAt(i + K) - '0') << (K - 1);  // 다음 비트 추가
    }
}
```

이 방식을 적용하면 전체 시간 복잡도도 $O(\lvert S\rvert)$로 개선할 수 있습니다.
